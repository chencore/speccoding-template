# Requirements

> **维护规则**：本文件是**项目整体需求**，仅在**人工明确要求**时修改。AI 不得擅自更新。

---

## 1. 项目定位

一款单人自媒体创作工作台，长期目标是覆盖"选题→文案→脚本→视频→音频→数据分析"全流程，辅助创作者高效产出 YouTube 内容。v0.1 为深切片版本，只做"选题 + 文案"两个环节做深，其余环节按版本递进。 `[v0.1 新增]` (R-v0.1-ck-1)

## 2. 目标用户

单人创作者（ck 本人），投放平台 YouTube。使用场景：在工作台内从选题灵感到可发布的文案一气呵成，借助 AI 智能体提效。 `[v0.1 新增]` (R-v0.1-ck-2)

## 3. 核心功能

- [ ] **选题环节**：AI 选题灵感生成（基于种子词扩展）；支持手动导入历史频道数据（CSV/粘贴）作为选题参考输入；不做 YouTube API 自动抓取（留 v0.2）。 `[v0.1 新增]` (R-v0.1-ck-3)
- [ ] **文案环节**：输出 YouTube 标题 / 描述 / 标签三类文案；支持多版本 A/B 生成与对比；不做封面文字、不做口播全文（属脚本环节，留 v0.2）。 `[v0.1 新增]` (R-v0.1-ck-4)
- [ ] **AI 智能体**：基于 `@earendil-works/pi-agent-core` 库集成（非子进程）；通过 `pi-ai` 统一 LLM 接口，默认 DeepSeek v4 pro，多家混用可切换；自定义工具（如"读历史文案""查选题库"）注册给 agent。 `[v0.1 新增]` (R-v0.1-ck-5)
- [ ] **数据持久化**：SQLite 三张表 `topics` / `copies` / `copy_versions`；支持历史记录、多版本对比、"采用/未采用"标记（为将来数据分析环节留数据）。 `[v0.1 新增]` (R-v0.1-ck-6)
- [ ] **选题库**：已采纳的选题自动进入选题库；支持 AI 按预设类型自动分类，并可在历史记录页按类型浏览、筛选和手动修正分类。 `[v0.1 新增]` (R-v0.1-ck-9)

## 4. 非功能需求

- **性能**：本地运行，单人单机，无并发压力；AI 调用响应以模型本身为准 `[v0.1 新增]`
- **合规**：API key 由本人通过环境变量配置，不做密钥管理 UI `[v0.1 新增]`
- **安全**：本地数据，无外部暴露面 `[v0.1 新增]`
- **多端**：v0.1 仅 Web 端（本地浏览器访问） `[v0.1 新增]`
- **运维**：TypeScript 全栈、零运维、`npm run dev` 起步 `[v0.1 新增]` (R-v0.1-ck-7)

## 5. 非目标（明确不做什么）

- 不做发布到 YouTube（只产出文案，不调 YouTube Publishing API） `[v0.1 新增]` (R-v0.1-ck-8)
- 不做视频/音频/脚本环节（深切片策略，留后续版本）
- 不做多用户/账号体系（单人工作台）
- 不做自动定时任务（如每日抓热点）
- 不做云端部署（本地运行）

## 6. 成功标准

- v0.1：能从种子词/历史数据生成选题，并基于选题产出多版本标题/描述/标签文案，所有产物持久化、可对比、可标记采用
- 长期：六环节闭环跑通，AI 智能体成为创作主驾驶
